# ADR 001: Clean Architecture - Layer separaation 
## Context
Without a cleanly defined structure any android project would degenerate into a project where 
ui, business logic, db access end up in the same file. Making it impossible
to maintain , test in isolation and fragile to future changes even though it runs (not best pratice).

Furthermore, with me (Ben) and Luca as the only developers, we need to be able to work in parallel. Without clear architectural boundaries, we will constantly step on each other's toes and generate merge conflicts.

### Our Solution
-   Adopting Clean Architecture with 4 layers and unilateral dependencies
- ui->domain<-data
**Domain Layer** - pure kotlin , zero dependencies android or firebase
- Containing: model, repository interaces, use cases. Heart of the Application. 
**Data Layer** - implements domain interfaces. Contaiing DTO's mappers , firebase implementations. Knows about Domain but not of UI.

**UI Layer** - Compose screens e Viewmodels. Depends from domain via use cases. NEVER IMPORTS Firebase directly
**Infra Layer** - For now is only a placeholder (though for net config, logging, analytics) not a part of ui nor data.

## Consequences 
 ## **Pro**
 - Domain and use cases testable with pure junit , zero android mock.
 - Changing Firebase with another backend requires us to rewrite only data layer but no changes to domain or ui
## **Cons**
 - Initial overhead: each feature requires AT Least 4 files instead of 1.
 - Much more boilerplate 

**Technical Debt**
- As mentioned before infra layer currently is completly empty. But our mind is thinking: structured loggin (Timber), analytics(Firebase Analytics) and crash reports.
- Security Risks are not mitigated and I Ben have left a few holes in our application such as: Firestore Rules implemented just to make the application work instead of real hardened rules. HardCoded Role Assignment (privilege escalation). Apk is unobsfucated for now exposing evth.No input sanitization Layer(could go into infra layer). Again weak password policy.
