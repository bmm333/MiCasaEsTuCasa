# ADR 011: Real-time Session Management and Moderation Sync
## Context
As part of our moderation and security system, we need the ability to instantly lock out users if an administrator bans or suspends them. Relying purely on Firebase Auth token revocation can take a long time to propagate. We needed a way for the mobile client to immediately detect a change in account standing and redirect the user out of the application in real-time, without polling the server constantly.

### Our Solution
We created a dedicated `SessionManager` in the Domain layer acting as a real-time reactive bridge between Firebase Auth and Firestore.

1. **CallbackFlow and Snapshot Listeners**: `SessionManager` exposes a `sessionStatus` Kotlin `Flow` built using `callbackFlow`. 
2. **Dynamic Binding**: When a user logs in (detected via `FirebaseAuth.AuthStateListener`), the manager automatically attaches a Firestore `addSnapshotListener` strictly to that user's document.
3. **Real-time Event Emission**: If an admin updates the user's `status` to `BANNED` or `SUSPENDED` from the Admin Panel, Firestore immediately pushes this update to the active Snapshot Listener on the client. The Flow emits the new `UserStatus`, which the UI (e.g. `MainViewModel` or `AuthViewModel`) observes, immediately terminating the user's session and returning them to the login screen.
4. **Automatic Cleanup**: When the user logs out (or is kicked out), `awaitClose` safely removes the Firestore listener, preventing memory leaks and background data usage.

## Consequences 
 ## **Pro**
 - Security: Moderation actions (bans/suspensions) take effect instantly on active clients, closing the 1-hour vulnerability window of JWT token refresh cycles.
 - Efficiency: We avoid continuous HTTP polling; Firestore snapshot listeners are lightweight and only cost a document read when the document actually changes.
 - Reactive Architecture: By exposing it as a `Flow`, any ViewModel can effortlessly observe the global session state.

## **Cons**
 - Coupling: The `SessionManager` technically mixes Firebase Auth and Firestore logic in one place.
 - Cost: Every time the user opens the app and authenticates, a Firestore read is consumed to establish the listener state.

**Technical Debt**
- The `SessionManager` currently runs continuously as long as the user is logged in. If we implement a complex offline-mode or background-mode, we should consider pausing the snapshot listener when the app is fully backgrounded to save battery and network bandwidth.
